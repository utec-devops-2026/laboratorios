# 🤖 Guía 10: El agente construye, el CI juzga

## 🎯 Objetivo

Usar un agente de código (Claude Code, GitHub Copilot agent mode, Cursor o similar) para mejorar el modelo
House Price **sin que el agente pueda decidir si su cambio es bueno**. Esa decisión la toma un juez
independiente que corre en GitHub Actions sobre cada pull request.

Al terminar tendrás:

- `AGENTS.md`: las reglas que el agente lee antes de trabajar.
- `src/gate/evaluate_gate.py` + `src/gate/baseline.json`: el juez y el baseline que debe superar.
- `.github/workflows/model-gate.yml`: el workflow que ejecuta al juez en cada PR y comenta el veredicto.
- `.github/CODEOWNERS`: protección de los archivos del juez y de los datos.
- Dos PRs abiertos por el agente: uno que el juez acepta y otro que bloquea.

Principio de la sesión 13: **el agente nunca es dueño del juez**. Procesos separados, datos ocultos,
chequeos en capas, feedback grueso (pasa / falla y un motivo).

## 📋 Tabla de responsabilidades

| Pieza | Quién la escribe | Quién la puede cambiar después |
|---|---|---|
| `src/models/`, `src/features/`, `configs/` | el agente | el agente (vía PR) |
| `src/gate/`, `src/data/`, `data/raw/`, `.github/` | tú (ingeniero MLOps) | solo tú |
| Decisión de merge | — | tú, leyendo el comentario del juez |

## 🏗️ Arquitectura

```
          escribe código                 abre PR                  comenta ✅ / ❌
 Agente ───────────────► rama agent/* ──────────► model-gate.yml ───────────────► Humano
 (sandbox)            src/models, src/features,      │                            hace merge
 lee AGENTS.md        configs                        │
                                                     ▼
                                     1. rutas protegidas intactas (git diff)
                                     2. datos reconstruidos desde raw + data contract
                                     3. entrena el candidato con el código del PR
                                     4. evaluate_gate.py: split fijo, sin fuga,
                                        R² y MAE vs baseline.json
```

El juez **no lee las métricas que imprime `train_model.py`**: recalcula todo con su propio código sobre el
holdout que él define (`random_state=42`, `test_size=0.2`).

## ✅ Prerrequisitos

- Laboratorio 13.2 terminado: pipeline con `data-processing`, `feature-engineering` y `model-training`,
  y `src/models/train_model.py` con el `quality_gate` de `configs/model_config.yaml`.
- Un agente de código instalado. Cualquiera sirve; lo importante es que lea `AGENTS.md`
  (Claude Code lee `CLAUDE.md`, haz un symlink o copia: `cp AGENTS.md CLAUDE.md`).
- `git` configurado para abrir PRs (`gh` CLI o la UI de GitHub).

## Paso 1 — Las reglas del agente: `AGENTS.md`

Crea `AGENTS.md` en la raíz del repo:

```markdown
# Reglas para agentes de código en este repositorio

Este repo entrena y publica el modelo House Price. Un juez automático (`.github/workflows/model-gate.yml`)
evalúa cada pull request sobre un holdout fijo. Tú construyes; el juez decide.

## Qué puedes hacer
- Editar `src/models/`, `src/features/`, `configs/` y el `README.md`.
- Cambiar el algoritmo, sus hiperparámetros o crear features nuevas a partir de las columnas de entrada.
- Ejecutar localmente el pipeline completo para comprobar tu cambio antes de abrir el PR:
  ```bash
  python src/data/run_processing.py --input data/raw/house_data.csv --output data/processed/cleaned_house_data.csv
  python src/data/validate.py --input data/processed/cleaned_house_data.csv
  python src/features/engineer.py --input data/processed/cleaned_house_data.csv --output data/processed/featured_house_data.csv --preprocessor models/trained/preprocessor.pkl
  python src/models/train_model.py --config configs/model_config.yaml --data data/processed/featured_house_data.csv --models-dir models
  python src/gate/evaluate_gate.py --cleaned data/processed/cleaned_house_data.csv --featured data/processed/featured_house_data.csv --model models/trained/house_price_model.pkl --baseline src/gate/baseline.json
  ```

## Qué no puedes hacer
- Tocar `.github/`, `src/gate/`, `src/data/` ni `data/raw/`. El juez rechaza el PR si cambian.
- Cambiar el split (`TEST_SIZE`, `RANDOM_STATE`) ni la columna `split`: el holdout es del juez.
- Crear features que usen el target `price` (por ejemplo `price_per_sqft`). Eso es fuga de datos.
- Modificar umbrales, baseline o métricas reportadas para que "pasen".
- Hacer commit de datos, modelos (`.pkl`) o credenciales. Nunca uses secrets ni URLs de producción.
- Hacer merge. Solo abres el PR; una persona lo revisa.

## Cómo entregar
- Una rama `agent/<tema>` y un PR contra `main` con: qué cambiaste, por qué y las métricas locales.
- Si el juez falla, lee su comentario en el PR y corrige la causa real; no el chequeo.
```

Las reglas son explícitas a propósito: en el reto 2 vas a ver qué pasa cuando el prompt las contradice.

## Paso 2 — El juez: `src/gate/evaluate_gate.py`

Crea `src/gate/__init__.py` vacío y `src/gate/evaluate_gate.py`:

```python
"""Juez independiente del modelo (model gate).

Se ejecuta en CI sobre cada pull request. No confía en las métricas que reporta
train_model.py: vuelve a calcular todo con su propio código sobre el holdout fijo.

Chequeos (todos deben pasar):
  1. split      el holdout (split == test) es exactamente el que define el juez
                (train_test_split con random_state=42, test_size=0.2 sobre los datos limpios)
  2. contract   los datos limpios cumplen el data contract (src/data/contract.py)
  3. leakage    ninguna feature se llama *price* ni correlaciona > 0.99 con el target
  4. metrics    R² sube al menos --min-gain sobre el baseline y el MAE no empeora
                más de --mae-tolerance (fracción)

Uso:
    python src/gate/evaluate_gate.py \
        --cleaned data/processed/cleaned_house_data.csv \
        --featured data/processed/featured_house_data.csv \
        --model models/trained/house_price_model.pkl \
        --baseline src/gate/baseline.json \
        --report reports/gate_report.json

Sale con código 1 si algún chequeo falla. Escribe también reports/gate_report.md
(el comentario que el workflow publica en el PR).
"""

import argparse
import json
import sys
from pathlib import Path

import joblib
import numpy as np
import pandas as pd
from sklearn.metrics import mean_absolute_error, r2_score
from sklearn.model_selection import train_test_split

ROOT = Path(__file__).resolve().parents[2]
sys.path.insert(0, str(ROOT / "src" / "data"))
from contract import check_contract  # noqa: E402

TARGET = "price"
TEST_SIZE = 0.2
RANDOM_STATE = 42
LEAK_CORR = 0.99


def check_split(cleaned: pd.DataFrame, featured: pd.DataFrame) -> dict:
    """El holdout del PR debe ser el mismo que el del juez (mismas casas)."""
    _, expected_test = train_test_split(cleaned, test_size=TEST_SIZE, random_state=RANDOM_STATE)
    actual_test = featured[featured["split"] == "test"]
    expected = sorted(expected_test[TARGET].round(2).tolist())
    actual = sorted(actual_test[TARGET].round(2).tolist())
    ok = expected == actual
    return {"check": "split", "ok": ok,
            "detail": f"test rows esperadas={len(expected)} recibidas={len(actual)}"
                      + ("" if ok else " — el holdout fue modificado")}


def check_data_contract(cleaned: pd.DataFrame) -> dict:
    violations = check_contract(cleaned, require_target=True)
    return {"check": "contract", "ok": not violations,
            "detail": "sin violaciones" if not violations else
            "; ".join(f"{v['check']}:{v['column']} ({v['rows']} filas)" for v in violations)}


def check_leakage(featured: pd.DataFrame, features: list[str]) -> dict:
    bad = [c for c in features if TARGET in c.lower()]
    corr = featured[features].corrwith(featured[TARGET]).abs()
    bad += [c for c in features if c not in bad and corr.get(c, 0) > LEAK_CORR]
    return {"check": "leakage", "ok": not bad,
            "detail": "ninguna feature deriva del target" if not bad else
            f"features sospechosas: {', '.join(bad)}"}


def check_metrics(model, featured: pd.DataFrame, features: list[str], baseline: dict,
                  min_gain: float, mae_tolerance: float) -> dict:
    test = featured[featured["split"] == "test"]
    pred = model.predict(test[features])
    r2 = float(r2_score(test[TARGET], pred))
    mae = float(mean_absolute_error(test[TARGET], pred))
    r2_ok = r2 >= baseline["r2"] + min_gain
    mae_ok = mae <= baseline["mae"] * (1 + mae_tolerance)
    reasons = []
    if not r2_ok:
        reasons.append(f"R² {r2:.4f} < baseline {baseline['r2']:.4f} + {min_gain}")
    if not mae_ok:
        reasons.append(f"MAE {mae:.0f} > baseline {baseline['mae']:.0f} × {1 + mae_tolerance:.2f}")
    return {"check": "metrics", "ok": r2_ok and mae_ok,
            "detail": "; ".join(reasons) if reasons else "mejora sobre el baseline",
            "candidate": {"r2": round(r2, 4), "mae": round(mae, 2), "n_test": int(len(test))},
            "baseline": baseline}


def to_markdown(report: dict) -> str:
    icon = lambda ok: "✅" if ok else "❌"
    lines = [f"## {'✅ Model gate: PASS' if report['passed'] else '❌ Model gate: FAIL'}", "",
             "| Chequeo | Resultado | Detalle |", "|---|---|---|"]
    for c in report["checks"]:
        lines.append(f"| {c['check']} | {icon(c['ok'])} | {c['detail']} |")
    m = next((c for c in report["checks"] if c["check"] == "metrics"), None)
    if m and "candidate" in m:
        lines += ["", "| Métrica | Baseline | Candidato |", "|---|---|---|",
                  f"| R² | {m['baseline']['r2']:.4f} | {m['candidate']['r2']:.4f} |",
                  f"| MAE | {m['baseline']['mae']:.0f} | {m['candidate']['mae']:.0f} |",
                  f"| filas de test | — | {m['candidate']['n_test']} |"]
    lines += ["", "_El juez recalcula todo sobre el holdout fijo; no usa las métricas del entrenamiento._"]
    return "\n".join(lines)


def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--cleaned", required=True)
    ap.add_argument("--featured", required=True)
    ap.add_argument("--model", required=True)
    ap.add_argument("--baseline", required=True)
    ap.add_argument("--report", default="reports/gate_report.json")
    ap.add_argument("--min-gain", type=float, default=0.003)
    ap.add_argument("--mae-tolerance", type=float, default=0.10)
    args = ap.parse_args()

    cleaned = pd.read_csv(args.cleaned)
    featured = pd.read_csv(args.featured)
    baseline = json.load(open(args.baseline))
    features = [c for c in featured.columns if c not in (TARGET, "split")]

    checks = [check_split(cleaned, featured), check_data_contract(cleaned),
              check_leakage(featured, features)]
    if all(c["ok"] for c in checks):
        model = joblib.load(args.model)
        checks.append(check_metrics(model, featured, features, baseline,
                                    args.min_gain, args.mae_tolerance))
    else:
        checks.append({"check": "metrics", "ok": False,
                       "detail": "no evaluado: falló un chequeo previo"})

    report = {"passed": all(c["ok"] for c in checks), "checks": checks}
    out = Path(args.report)
    out.parent.mkdir(parents=True, exist_ok=True)
    out.write_text(json.dumps(report, indent=2, ensure_ascii=False))
    out.with_suffix(".md").write_text(to_markdown(report))
    print(to_markdown(report))
    sys.exit(0 if report["passed"] else 1)


if __name__ == "__main__":
    main()
```

## Paso 3 — El workflow: `.github/workflows/model-gate.yml`

```yaml
# Juez independiente: se ejecuta en cada pull request hacia main.
# El agente puede cambiar el modelo, las features y la configuración; este workflow
# reconstruye los datos desde raw, entrena el candidato con el código del PR y lo
# evalúa con src/gate/evaluate_gate.py sobre el holdout fijo.
name: Model Gate

on:
  pull_request:
    branches: [main]

permissions:
  contents: read
  pull-requests: write

env:
  PROTECTED: '^(\.github/|src/gate/|src/data/|data/raw/)'

jobs:
  gate:
    name: Model gate (juez)
    runs-on: ubuntu-latest

    steps:
      - name: Checkout (historia completa para el diff)
        uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: 1. Rutas protegidas intactas
        run: |
          CHANGED=$(git diff --name-only origin/${{ github.base_ref }}...HEAD)
          echo "Archivos cambiados en el PR:"; echo "$CHANGED"
          if echo "$CHANGED" | grep -E "$PROTECTED"; then
            echo "::error::El PR modifica archivos del juez o de los datos. Solo un humano puede hacerlo."
            exit 1
          fi

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: "3.11.9"

      - name: Install dependencies
        run: |
          python -m pip install --upgrade pip
          pip install -r requirements.txt

      - name: 2. Reconstruir datos desde raw (no se confía en CSVs del PR)
        run: |
          mkdir -p data/processed models/trained reports
          python src/data/run_processing.py --input data/raw/house_data.csv --output data/processed/cleaned_house_data.csv
          python src/data/validate.py --input data/processed/cleaned_house_data.csv
          python src/features/engineer.py --input data/processed/cleaned_house_data.csv --output data/processed/featured_house_data.csv --preprocessor models/trained/preprocessor.pkl

      - name: 3. Entrenar el candidato con el código del PR
        run: |
          python src/models/train_model.py --config configs/model_config.yaml --data data/processed/featured_house_data.csv --models-dir models

      - name: 4. Juez independiente
        run: |
          python src/gate/evaluate_gate.py \
            --cleaned data/processed/cleaned_house_data.csv \
            --featured data/processed/featured_house_data.csv \
            --model models/trained/house_price_model.pkl \
            --baseline src/gate/baseline.json \
            --report reports/gate_report.json

      - name: Comentar el veredicto en el PR
        if: always()
        uses: actions/github-script@v7
        with:
          script: |
            const fs = require('fs');
            const path = 'reports/gate_report.md';
            const body = fs.existsSync(path)
              ? fs.readFileSync(path, 'utf8')
              : '## ❌ Model gate: FAIL\n\nEl pipeline falló antes de llegar al juez (rutas protegidas, contrato o entrenamiento). Revisa los logs del job.';
            await github.rest.issues.createComment({
              owner: context.repo.owner, repo: context.repo.repo,
              issue_number: context.issue.number, body,
            });

      - name: Upload gate report
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: gate-report
          path: reports/
```

Cuatro detalles que importan:

1. `fetch-depth: 0` para que `git diff origin/main...HEAD` vea toda la rama del PR.
2. Los CSV se regeneran desde `data/raw`: si el agente subió un `featured_house_data.csv` "mejorado", se ignora.
3. El comentario se publica con `if: always()`: el PR recibe el veredicto aunque el job falle.
4. `permissions` mínimos: `contents: read` y `pull-requests: write`. El agente nunca ve `DOCKERHUB_TOKEN`
   ni ningún secret del pipeline principal.

## Paso 4 — Proteger al juez

`.github/CODEOWNERS` (reemplaza `@TU-USUARIO` por tu usuario de GitHub):

```
# Archivos del juez y de los datos: solo el dueño del repo puede aprobar cambios.
# Con "Require review from Code Owners" activo en la rama main, GitHub exige tu
# aprobación antes de hacer merge de cualquier PR que los toque.
.github/     @TU-USUARIO
src/gate/    @TU-USUARIO
src/data/    @TU-USUARIO
data/raw/    @TU-USUARIO
```

Luego en **Settings → Branches → Add branch ruleset** para `main`:

- **Require a pull request before merging** y **Require review from Code Owners**.
- **Require status checks to pass**: agrega `Model gate (juez)`.
- Si tu plan lo permite (repos públicos o GitHub Pro / organización): **Require workflows to pass before
  merging** apuntando a `model-gate.yml` de la rama `main`. Esto ejecuta la versión del workflow que está en
  `main`, no la del PR.

> ⚠️ **Limitación honesta.** En el evento `pull_request`, GitHub ejecuta el workflow **tal como está en la rama
> del PR**. Un agente podría editar `model-gate.yml` para que siempre pase. El paso "rutas protegidas" lo detecta
> solo si el agente no borró también ese paso. La protección real es la combinación: CODEOWNERS + revisión
> obligatoria + status check requerido (+ "Require workflows" si está disponible). Por eso el humano revisa
> el diff de `.github/` antes de hacer merge. Esa es una de las "diez reglas" de la sesión 13.

Haz commit de todo esto directamente en `main` (eres el dueño del juez):

```bash
git checkout main
git add AGENTS.md src/gate .github/workflows/model-gate.yml .github/CODEOWNERS
git commit -m "feat: add independent model gate for agent PRs"
git push origin main
```

## 🔍 Troubleshooting

| Síntoma | Causa | Solución |
|---|---|---|
| `FileNotFoundError: models/trained/preprocessor.pkl` | `engineer.py` no crea la carpeta | `mkdir -p models/trained` antes (ya está en el workflow) |
| `Yaml file 'mlruns/0/meta.yaml' does not exist` | `mlruns/` de otra versión de MLflow | `rm -rf mlruns` y volver a entrenar |
| El juez pasa con el baseline sin cambios | `baseline.json` tiene valores más bajos que tu modelo real | copia R² y MAE de tu `model_config.yaml` |
| `git diff` no encuentra `origin/main` | `fetch-depth: 1` | usa `fetch-depth: 0` en el checkout |
| El comentario no aparece en el PR | falta `pull-requests: write` | revisa `permissions` del workflow |
| R² del RandomForest cambia entre corridas | sin `random_state` | fija `random_state: 42` en `parameters` |

## ⭐ Opcional: el juez explica el veredicto con GitHub Models

GitHub Models se puede llamar desde Actions con el `GITHUB_TOKEN` del propio job (sin API key):

```yaml
permissions:
  contents: read
  pull-requests: write
  models: read
# ...
      - name: Explicación en lenguaje natural
        if: always()
        run: |
          REPORT=$(cat reports/gate_report.md)
          curl -s https://models.github.ai/inference/chat/completions \
            -H "Authorization: Bearer ${{ secrets.GITHUB_TOKEN }}" \
            -H "Content-Type: application/json" \
            -d "$(jq -n --arg r "$REPORT" '{model:"openai/gpt-4o-mini",
                 messages:[{role:"system",content:"Eres un revisor MLOps. Explica en 3 líneas, en español, el veredicto del juez. No cambies la decisión."},
                           {role:"user",content:$r}]}')" \
            | jq -r '.choices[0].message.content' > reports/gate_explained.md
```

Regla de la sesión 15: **el LLM explica, los umbrales deciden.** Si el resumen contradice el veredicto, gana
el veredicto.
